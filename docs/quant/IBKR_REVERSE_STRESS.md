# AtlasPM v0.4.13 — Hypothetical Reverse Margin Stress

**Read-only, offline, synthetic-only validation.** This module accepts an existing private v0.4.12 multiasset risk budget report and a separately supplied reverse-shock assumptions file. It solves elementary mathematical shock thresholds for an imagined portfolio. It does **not** determine real IBKR liquidation levels or independently verify any debt, collateral, haircut or trade permission.

## Windows PowerShell

Use the v0.4.12 file already generated by the previous synthetic test.

```powershell

.\.venv\Scripts\python.exe -m pip install -e .

.\.venv\Scripts\python.exe -m unittest discover -s tests -v

.\.venv\Scripts\python.exe -m atlaspm.cli ibkr-reverse-stress --budget local_data\ibkr_multiasset_budget.json --assumptions examples\ibkr_reverse_stress_synthetic.json --output local_data\ibkr_reverse_stress.json
```

All example scenario IDs, values and dates are fictional. Do not upload any real `local_data/` report to GitHub, ChatGPT or a public issue. CLI output contains only a masked account suffix, scenario indices, issue codes and statuses. All actual amounts and assumed shock fractions stay in ignored local files. The synthetic example uses exactly the three hypothetical risk sleeves from v0.4.12, not real IBKR positions.

## What reverse stress measures

Each synthetic case declares a **maintenance requirement multiplier**, assumed flat APR, holding period, and a per-asset relative shock multiplier in `[0,1]`. The configuration defines a maximum uniform market decline fraction (1.0 means explore 0–100%) and an assumed excess-liquidity-to-NLV floor (strictly below 1).

The relative multipliers translate a single hypothetical market decline `d` to a sleeve-specific loss:

```text
loss_per_full_unit = sum(value_i * relative_shock_multiplier_i)
market_loss(d) = d * loss_per_full_unit

new_simple_interest = unverified_principal * assumed_APR * horizon_days / 365

NLV(d) = starting_NLV - new_simple_interest - market_loss(d)
ELV(d) = starting_ELV - new_simple_interest - market_loss(d)
maintenance = starting_maintenance * hypothetical_multiplier
excess(d) = ELV(d) - maintenance
buffer(d) = excess(d) / NLV(d)   [when NLV(d) > 0]
```

The code analytically finds the **first** d in the explicitly scanned interval at which any selected condition touches its mathematical limit: zero NLV; zero maintenance excess; or excess equal to the chosen fraction of positive NLV. Results can indicate:

- `ILLUSTRATIVE_NO_THRESHOLD_IN_SCAN_RANGE`: none reached up to the provided maximum drawdown, not proof of true safety.
- `ILLUSTRATIVE_THRESHOLD_WITHIN_SCAN`: at least one limit is reached for some hypothetical decline in the tested interval.
- `ILLUSTRATIVE_ALREADY_AT_THRESHOLD`: interest/maintenance assumptions put the snapshot at or beyond a limit even with no new market price loss.

The full local JSON contains numerical fractions and assumptions. Console output intentionally omits case titles and exact shock fractions. A separate financing-cost-budget flag checks assumed annual loan interest relative to starting NLV using the previously supplied v0.4.12 interest limit.

**Boundaries are closed-form static algebra, not an IBKR margin call model.** In particular, changing assets' haircuts, real Portfolio Margin concentration add-ons, intraday rules, currency conversions, liquidation selection/timing, expected returns, realized volatility, dynamic rebalancing and tax/transaction costs are unmodeled.

v0.4.12's prior result does not expose independently verified initial margin. Thus this version does **not** compute a real available-funds or buying-power threshold. It also does not double-subtract previously reported loan principal from NLV or reuse already-accrued interest as a new cost.

## Persistent trust boundary

A JSON file saved earlier is **unsigned and user controlled**. Replaying it is not broker authentication, freshness validation or credit approval. Input checks reject unsupported upstream source types and any claimed execution authorization. The module never performs network requests or places orders; the following flags are always false:

```json
{
  "IBKR_financing_debt_separately_verified": false,
  "broker_treasury_collateral_verified": false,
  "IBKR_order_bound_whatif_verified": false,
  "ready_for_institutional_risk_gate": false,
  "live_execution_enabled": false
}
```

See prior [v0.4.12 multiasset budget documentation](IBKR_MULTI_ASSET_BUDGET.md) and [v0.4.11 stress accounting assumptions](IBKR_MARGIN_STRESS.md).
